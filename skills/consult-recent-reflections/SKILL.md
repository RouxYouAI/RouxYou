# Consult Recent Reflections

## When to use

You're about to:
- Draft a /propose of a category you've drafted before
- Verify (shadow) a proposal that looks like one you've seen
- Decide whether to escalate or handle locally

Before deciding, check whether your past self already judged similar work.

## What's in the log

`state/reflection_log.jsonl` — v3-generated post-execution quality judgments on completed proposals. Each entry:

```json
{
  "proposal_id": "...",
  "category": "config|code|meta|...",
  "title": "...",
  "outcome": "applied|rolled-back|stuck",
  "quality": "HIGH|MEDIUM|LOW",
  "rationale": "...",
  "timestamp": "2026-05-..."
}
```

Generated by `shared/post_exec_reflection.py` cron.

## Steps

1. **Identify category + shape** of the current action.
2. **Read last ~20 entries** from `reflection_log.jsonl` (already injected as `recent_reflections_block` in /companion chat — last 3 are always-on; ask for more if needed).
3. **Look for matches:**
   - Same category + LOW quality + rolled-back → strong signal current action will repeat the mistake. Slow down, ask why.
   - Same category + HIGH quality + applied → pattern works, follow it.
   - No similar entries → new territory, default to extra verification.
4. **Cite the relevant entry** in your decision. "Past reflection: LOW on similar config change because EVIDENCE was fabricated" beats "I have a feeling this might fail."

## Honesty rule

If you don't have a relevant reflection, say so. Don't invent one. The pattern of inventing past sessions to support a current decision IS one of the failure modes the reflection log exists to catch.

## Files involved

- `state/reflection_log.jsonl` — the data
- `shared/post_exec_reflection.py` — generator cron
- `shared/companion.py::_recent_reflections()` — chat-context loader (n=3 default)
